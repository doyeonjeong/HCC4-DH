# R5 — 게이트와 실패 복귀

`rules.yaml`이 아래 게이트의 값을 보관하는 단일 SSOT다. 에이전트는 게이트 결과를 직접 승인하거나 고치지 않고 `gate-judge`가 읽기 전용으로 판정한다.

| Gate | 통과 조건 | 실패 시 복귀 |
|---|---|---|
| G1 기준·불변 조건 | PRD, design, story-service 파일 존재. 서비스 스토리 1~5개, 불변 조건 1~2개. 화면 명세가 `seller` 이외 역할에 `sale_requested`를 허용하지 않고 운영자 체크리스트 수동 검수를 유지 | S1 범위 선택 |
| G2 범위 | `flow.json`에 선택한 MVP 흐름과 화면 ID 3개가 있고 각 화면이 MVP 사용자 스토리와 연결됨 | S1 범위 선택 |
| G3 레퍼런스 | `uibowl.json`에 UI Bowl 원본 링크 2개 이상, 화면별 관찰 노트가 있음 | S2 레퍼런스 수집 |
| G4 키스크린 | 세 화면 각각에 목적, 역할, 필수 콘텐츠, 대표 상태가 정의됨 | S3 핵심 화면 정의 |
| G5 시안 승인 | 사람이 `approval.md`에 시안 ID와 현재 입력 지문을 확인해 승인하고, 오케스트레이터가 같은 지문으로 `approval.json`을 기록함 | G4로 복귀하거나 사람 응답 대기 |
| G6 토큰 | 색상 값이 `docs/design.md` 팔레트에 있고, 간격은 4/8/12/16/24/32/48/64px, 모서리는 0/16/24/9999px 중 하나. 서체는 Pretendard 또는 문서에 적힌 대체 글꼴 | S4 토큰 구성 |
| G7 Figma 결과 | Figma manifest에 필수 프레임 3개와 링크가 있고 각 프레임은 390×844 기준. 금지된 MVP 밖 기능 문자열·액션이 화면 명세에 없음. `gate-results.json` 전 게이트가 통과 | 실패 유형에 따라 S3/S4/S5 |

## MVP 불변 조건 검사

- `sale_requested` 액션의 actor는 `seller`여야 한다.
- 판매 검수는 운영자 체크리스트를 요구하며 자동 AI 1차 검수로 표시하지 않는다.
- MVP 화면 명세에 `for_sale`, `suspended`, 구매, 결제, 정산 기능이 포함되면 G1 또는 G7에서 실패한다.
- 판매 신청 상태의 MVP 범위는 `draft`, `pending`, `revision_requested`, `approved`, `rejected`다. `suspended`는 MVP 결과물에서 허용하지 않는다.

## 사람 승인 지점

G5 한 곳에서 사람이 키스크린 시안을 고른다. 사람은 `runs/<slug>/approval.md`에 결정하고, 오케스트레이터는 현재 입력의 SHA-256과 결정을 `approval.json`에 기록한다. 입력 파일의 해시가 바뀌면 승인은 무효가 된다. G7 통과 뒤에는 Public 제출 자료를 준비한다.

## 현재 수작업 기준 상태

R1-B 실제 과거 수작업 흐름은 확인되지 않았다. 이를 자동 게이트 통과로 간주하거나 실제 이력으로 표현하지 않는다. 이 하네스의 결과는 새 작업에 대한 PoC로 표시한다.
