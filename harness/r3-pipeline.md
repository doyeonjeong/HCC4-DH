# R3 — 단계 흐름

| 단계 | 작업 | 다음으로 넘어가는 조건 |
| --- | --- | --- |
| P1 | PRD, 역할, 사용자 이야기, 서비스 불변조건 정리 | 한 흐름의 목적과 범위를 확인 |
| P2 | UI 레퍼런스 조사, 토큰·컴포넌트·Figma 시스템 페이지 작성 | 규칙과 디자인 문서가 동기화되고 G1 실행 준비 완료 |
| G1 | Figma 시스템 페이지 기계 검사 | `tools/` 게이트가 통과 |
| P3 | 승인된 컴포넌트로 화면과 상태 작성 | 모든 화면이 사용자 이야기와 연결 |
| G2 | Figma 화면 페이지 기계 검사 | 게이트와 화면 불변조건 통과 |
| G3 | 사람이 Figma 결과와 요약을 검토하고 승인 | 프로젝트 소유자가 승인 기록 |
| P4 | HTML 프로토타입 제작, Chrome 시각 QA, 결함 표 작성 | 화면별 비교와 필수 결함 점검 완료 |

실패한 게이트는 해당 설계 단계로 돌아갑니다. 규칙·토큰 문제는 P2로, 화면 구조 문제는 P3로 돌아가며, 규칙 수정에는 사람의 승인과 `.rules-unlock`이 필요합니다.
